# M5 Mac 应用走查清单（草稿）

会话里不启动应用、不创建窗口（m5-plan v2.5 决定 4）：视图代码只经过编译。下面这些要由用户在 Mac 上实际打开应用看，逐项打勾或记下问题。每个界面任务（M5-7 起）往这里追加。

## 怎么打开（M5-7 阶段，开发模式）

1. 起一个开发模式的假系统 abroadd（不碰本机网络；`--fake-main-proxy` 接上假的出口检查和假虚拟机，能走完引导）：
   `go build -o /tmp/abroadd ./cmd/abroadd && /tmp/abroadd --fake-system --fake-main-proxy --state-dir /tmp/abroad-walk/st`
2. 另开一个终端：`cd app && swift build && ABROAD_SOCKET=/tmp/abroad-walk/st/api.sock .build/debug/ClaudeAbroad`
   （`.app` 包的组装和 ad-hoc 签名在后面的任务里写成脚本；现在直接运行可执行文件。）
3. 看完：在第二个终端按 Ctrl+C 退出应用，第一个终端按 Ctrl+C 停 abroadd，删掉 `/tmp/abroad-walk`。

## M5-8：安装引导与主代理页面

开发模式下属主就是完全信任的调用方：敏感操作直接成功，看不到终端退路。要看终端退路，可在真实模式（以 root 运行的 abroadd、以普通用户打开应用）走查；或者记下“待真机看”。

### 安装引导（新的状态目录时打开应用即进入）

- [ ] 第 1 步“欢迎”：做什么——看说明，点“下一步”；应该看到——步骤条四步，当前一步加粗
- [ ] 第 2 步“后台服务”：先不启动 abroadd 打开应用——显示手动加载的说明、命令（可选中）和“这是临时做法”；“下一步”不可点；再启动 abroadd——几十秒内自动前进到第 3 步
- [ ] 第 3 步“配置主代理”：内嵌主代理页面；没应用主代理时“完成”不可点；应用成功后点“重新检查”（或应用后自动）——“完成”可点
- [ ] 第 3 步点“完成”被后台拒绝时（例如删掉状态目录里的出口基准后）——停在第 3 步，红框里三段显示后台的原因
- [ ] 第 4 步“完成”：显示完成说明；关掉窗口再打开——直接进首页，不再进入引导

### 主代理页面

- [ ] 来源列表：每行只有名字、种类、节点数、更新时间（没有订阅地址和服务器）；订阅有“更新订阅”，都有“删除”
- [ ] 添加来源——订阅地址：填名字和地址，点“添加”；地址框马上清空；未启用且没勾“经本机网络抓取订阅”时，出现说明（会看到你本机的地址），勾上后要重新填地址再提交（假系统不抓取订阅，会显示失败原因）
- [ ] 添加来源——本地配置文件：“选择文件…”或把文件拖进来，显示文件名；添加后列表多一行
- [ ] 添加来源——手动节点：类型 SOCKS5/HTTP、服务器、端口、用户名、密码（密码不回显）；端口不对时提示、不提交；提交后表单的服务器、端口、用户名、密码都清空
- [ ] 更新订阅：未启用时提示要经本机网络，按钮变成“经本机网络更新”；更新后选中的节点不在了时出现橙色提示
- [ ] 选节点：出口节点下拉；“加一跳中转”菜单，可去掉；“应用主代理”——正在应用的转圈和文字，成功后绿色的“主代理已应用：出口在 US（America/Los_Angeles）”
- [ ] 应用失败：红框三段原样；回退成功时下面有“已经回到原来的主代理”，回退没完成时是橙色的提示
- [ ] 已启用时应用、地区会变：弹出通用的确认框（地区 A → B、要结束的进程），取消不变，确认后成功
- [ ] 第一跳是局域网节点：弹出“确认局域网节点”，写着“节点“名字”在你的局域网里，确认后虚拟机可以连到这个地址。”；确认后再点应用就能成功
- [ ] 检查主代理：显示“主代理可用：出口在 …，规则 …”，没有任何地址
- [ ] 终端退路（真实模式、普通用户）：添加订阅时出现两步说明——第一步临时文件的路径，第二步要执行的命令（不含订阅地址和密码）；点“执行完了”后临时文件被删除；拷贝命令可用

### 与原型（ui/design/index.html）的不同

- 原型的主窗口是侧边栏（总览、主代理、分流出口……），这里先用两个标签页（首页、主代理），侧边栏随后续页面一起做。
- 原型的“添加主代理的节点来源”是弹出的对话框，按钮叫“导入并验证”；这里是页面里的一块表单，按钮叫“添加”。
- 原型的本地文件单个上限 8 MiB、可以直接粘贴 YAML；这里上限 2 MiB（和后台的请求体上限一致），暂不支持粘贴。
- 原型的“通过本机网络下载这份订阅”说明“以 Clash 客户端身份下载”；这里的说明按后台的要求写（未启用时才需要、会暴露本机地址）。
- 局域网节点的确认框、终端退路的两步说明原型里没有（按设计文字做）。

## M5-9：其余页面和设置窗口

主窗口的标签页：首页、主代理、分流出口、应用分流、环境检测、地区、引擎与虚拟机。设置窗口用 ⌘, 打开。开发模式的假系统没有环境检测、没有分流出口的真实检查，下面相应的条目写“真机看”。

### 每个页面共有

- [ ] 停掉 abroadd 后切到任一页面：显示“后台服务没有运行”的横幅和“重试”，不是空白
- [ ] 后台回错误时：红框三段显示，下面有“重试”

### 分流出口

- [ ] 没有出口时显示“没有分流出口：所有流量走主代理”
- [ ] 导入出口：填标签、选类型（wireguard / openvpn / clash）、选配置文件，点“添加”；列表多一张卡片（标签、类型、可用 / 不可用、各项检查结果、连接数）
- [ ] “检查”：卡片上的结果更新（真机看）
- [ ] 删除一个被规则引用的出口：红框原样显示后台的拒绝（列出规则序号）
- [ ] 真实模式、普通用户：导入或删除时弹出终端退路，命令是 `sudo abroad exit add <标签> --kind … --file <你选的文件>` / `sudo abroad exit rm <标签>`

### 应用分流

- [ ] 列表：先是在联网的应用（图标、名字、应用 ID、连接数），再是只有规则的应用；右侧菜单显示当前动作（没有规则时“（默认）”）
- [ ] 把一个 .app 从 Finder 拖进列表：多一条“主代理”规则，应用 ID 是它的 Bundle ID（小写）
- [ ] 改成“阻止”（收紧）：直接生效
- [ ] 改成“本机网络”（放松）：真实模式普通用户下显示“这个改动放松了保护，需要本人授权”和后台的原因，并弹出终端退路 `sudo abroad app set <应用> direct`
- [ ] 把 Claude 或代理软件改成“本机网络”：红框原样显示后台的拒绝
- [ ] 动作菜单：本机网络、阻止、主代理之后列出各分流出口（“分流出口 <标签>”）；选了之后规则指向那个出口
- [ ] 终端里执行完 `sudo abroad app set …` 后点“执行完了”：页面马上显示终端里改的规则；之后在页面上改别的应用，终端里改的那条还在（先读后写）
- [ ] “断开受影响的连接”默认不勾
- [ ] 底部三行说明：本机网络的应用访问 Claude 域名仍走主代理、Claude 不能设本机网络、代理软件不能设本机网络

### 环境检测（真机看；假系统显示“这个模式不提供”）

- [ ] 分“硬性项”“警告项”两组，每项有结果（通过 / 不通过 / 无法判断 / 已跳过）、说明、修复办法
- [ ] 警告项的开关可用；关掉后结果变成“已跳过”
- [ ] 硬性项的开关灰着，鼠标停留显示原因
- [ ] 工具栏“立即重新检测”（只在启用时可用：未启用时显示后台的说明）
- [ ] “设备体检”显示“在以后的版本提供”

### 地区

- [ ] 显示目标（时区、语言、地区格式）和来源（跟随出口 / 手动指定）；没有目标时显示“还没有锁定目标地区”
- [ ] 填时区和语言点“切换到这个地区”：地区不变时直接成功，显示“地区已切换”
- [ ] 已启用、地区会变：弹出通用确认框（地区 A → B、要结束的进程）；真实模式普通用户下先弹终端退路 `sudo abroad region set …`
- [ ] “跟随出口”
- [ ] 回国后有没还原的项时：这里和首页都显示“待还原的项”

### 引擎与虚拟机

- [ ] 显示 agent 版本、内核、运行时间、各引擎的状态和重启次数；虚拟机重启过时橙色提示
- [ ] 虚拟机不可达时显示“虚拟机不可达”，不是报错

### 设置窗口（⌘,）

- [ ] 通用：“调用方签名校验：未启用”的说明
- [ ] 环境检测：警告项的开关（和环境检测页同步）；硬性项不能关的说明
- [ ] 回国与 Claude：进程清单列出回国会结束的 Claude 进程（PID、应用、命令）和没能确认的项；没有时写“现在没有要结束的 Claude 进程”；打开这一页不会弹出回国确认、不改任何东西；启动管控“在以后的版本提供”
- [ ] 高级：命令行工具的位置和用法、签名校验的说明、诊断包“暂不提供”、卸载“在正式安装包里提供”

### 与原型（ui/design/index.html）的不同

- 原型是侧边栏（总览、主代理、分流出口、应用分流、环境检测、地区、引擎），这里是标签页；第一个页面原型叫“总览”，这里叫“首页”。
- 原型的分流出口支持 Clash 订阅、配置文件、分享链接、手动节点四种导入；这里只有选配置文件（wireguard / openvpn / clash 三种类型），订阅、分享链接、手动节点随后续任务。
- 原型的设置窗口有诊断包按钮；后台没有诊断包的接口，这里写“暂不提供”。
- 原型的环境检测有设备体检的结果；这里显示“在以后的版本提供”。

## M5-10：确认流程与通知

开发模式下属主就是完全信任的调用方，确认之后直接成功；终端退路要在真实模式普通用户下看。系统通知只有打包成 .app 后才会出现（直接运行 .build/debug/ClaudeAbroad 不发通知，这是设计：没有应用包的进程调用通知中心会崩溃）。

### 四种确认框（同一个确认框）

- [ ] 一键回国：弹出确认框，列出要结束的 Claude 进程、没能确认的项；“确认”灰着，显示“3 秒后可以确认”，3 秒后可点，下面显示“确认码 N 秒内有效”在倒数
- [ ] 启用（地区会变时）：确认框多一行“地区变化：A → B”
- [ ] 应用主代理（已启用、地区会变时）：同上
- [ ] 切换地区（会变时）：同上
- [ ] 有确认框时，菜单和首页的启用、回国按钮灰着；不会叠出第二个确认框
- [ ] 点“取消”：确认框关掉，什么都没变
- [ ] 点“确认”后到操作结束之间：显示“正在执行…”，“取消”灰着，按 Esc 或点外面关不掉确认框
- [ ] 确认码失效后重新发起、而后台这次不再要求确认（例如地区已不会变）：确认框关掉，窗口顶部显示“这次不需要确认，已完成”
- [ ] 过期：开着确认框等 60 秒以上——显示红色“已过期，请重新发起”，“确认”不可点，只能取消后重新发起
- [ ] 确认码失效后重新确认：打开回国确认框后，再启动或关掉一个 Claude 进程，然后点确认——确认框不关，顶部橙色提示“确认码已失效，下面是重新取到的内容”，进程清单是新的，又要等 3 秒再点一次
- [ ] 确认之后要求本人授权（真实模式普通用户）：弹出终端退路，执行完点“执行完了”后状态更新

### 通知（打包成 .app 后看）

- [ ] 第一次要发通知时系统询问通知权限（之前不会问）
- [ ] 保护断开：断开主代理的网络或让出口检查不通过——通知“保护断开：代理流量已关闭：<原因>”；同一原因不会反复弹
- [ ] 保护恢复：恢复后通知“保护已恢复”
- [ ] 自己点“停用”“一键回国”时不弹“保护断开”
- [ ] 自己更换主代理（已启用时）：成功时不弹“保护断开”“保护已恢复”；失败时只弹“更换主代理失败”
- [ ] “保护断开”的正文是中文的原因名称（例如“主代理的出口检查没有通过”）加后台的说明，不是英文代码
- [ ] 更换主代理失败：已回退 / 回退没完成各一种文字
- [ ] 回国完成：“已回国：本机网络已恢复”；有没还原的项时写出项目名
- [ ] 地区就绪：启用、地区写入且环境检测通过后通知“地区已就绪”，带“打开 Claude”按钮；点了才打开 Claude，不点不会自己打开
- [ ] 后台重启后重新连上：不会把当前状态补发成通知
- [ ] 通知里没有出口 IP、订阅地址、节点地址
- [ ] 设置 → 通用 → “发送通知”关掉后不再弹任何通知；重开应用后开关保持
