## 准备（两级共用，只做一次）

1. 打包应用：`scripts/dev/app-bundle.sh`（编译、组装 `app/.build/bundle/ClaudeAbroad.app`、临时签名；不安装、不启动）。约 1–3 分钟。
2. 第二级还要：`go build -o scripts/dev/out/bin/ ./cmd/abroadd ./cmd/abroad-vm ./cmd/abroad ./cmd/abroad-dev`；虚拟机镜像 `guest/out` 已经有（M2 起就有；没有时跑一次 `scripts/dev/vm-up.sh --no-panic`）。

## 第一级：假系统走查

执行 `scripts/m5/walk-fake.sh`：它启动假系统模式的 abroadd（带假主代理），再打开应用。应用开着时，在脚本的终端里按：

- `d`：只停假后台（应用不动）；
- `u`：用同一个状态目录、同一个 socket 路径把假后台再起来（应用自动重连；引导进度、主代理、出口基准都还在）；
- `q`：全部停掉并清理（在菜单栏图标里点“退出 Claude 出国”也一样）。

`scripts/m5/walk-fake.sh --app-first` 先打开应用、等你按回车才起假后台（L1-03 用）。

**这个模式下是假的或不提供的**（看到这些不算问题）：
- 环境检测：假系统没有，环境检测页显示“这个模式不提供”；
- 主代理的出口：假的出口检查，出口固定是文档用的地址（203.0.113.7，US）；
- 订阅地址：假系统不抓取订阅，添加订阅会显示失败原因（本地配置文件和手动节点可以加）；
- 分流出口：可以添加，但没有真实的检查（结果由假实现给出）；
- 回国时的 Claude 进程清单：假进程表，通常是 0 个；
- 敏感操作：你就是假后台的属主，直接成功，**看不到“这一步请在终端执行”**（终端退路在第二级看）；
- 系统通知：只有从应用包运行才会出现；第一次发通知时系统会询问权限。

每项编号后面括号里是对应的完成标准（见文末对照表）。

## 第二级：真机走查

**前提**：M2、M3、M4 的真机脚本都已通过；没有开别的代理软件的 TUN 或 VPN、系统代理；准备好一个远端或局域网节点的 Clash YAML。

**执行**（在这台 Mac 上、不需要 Claude Code 会话的时候）：

```sh
scripts/m5/run.sh --check-only     # 先只做前提检查（只读，不要 sudo）
sudo M5_NODES=<节点文件> M5_M2_PASSED=1 M5_M3_PASSED=1 M5_M4_PASSED=1 scripts/m5/run.sh
```

脚本会：拍网络和地区的快照 → 启动死人开关（45 分钟后自动恢复）→ 以真实模式启动 abroadd（本地接口在 `/var/run/claude-abroad`，应用和命令行都用这个默认位置）→ 在 `/usr/local/bin/abroad` 放一个指向测试安装的命令行（原来没有时才放）→ 提示你以自己的身份在另一个终端执行 `open app/.build/bundle/ClaudeAbroad.app` → 逐个检查点等你在应用里做完、按回车，经接口核对 → 收尾时执行恢复脚本。

需要本人授权的操作（添加来源、应用主代理、启用而地区会变、一键回国）在应用里会弹出“这一步请在终端执行”和 `sudo abroad …` 的命令：复制到终端执行（会问密码，命令行自己也会打印预览让你确认）。系统授权（不用终端）等 M5-3。

| 编号 | 在应用里做什么 | 脚本核对什么 | 对应 |
|---|---|---|---|
| P1 | 打开应用，进入安装引导；“后台服务”一步看到已连上，点“下一步” | 引导的后台服务一步已完成 | C10、C13 |
| P2 | “配置主代理”：添加来源（本地配置文件选 M5_NODES）→ 选出口节点 → “应用主代理”（按提示在终端执行命令） | 有来源、选了节点、出口基准已建立 | C3、C5、C13 |
| P3 | 点“完成”，进入首页 | 安装引导已完成 | C10、C13 |
| P4 | 菜单栏或首页点“启用”（确认框等 3 秒再确认；要本人授权时在终端执行）。**这一步接管本机网络** | 已启用、闸门开、出口信息有了 | C12、C13 |
| P5 | 点“停用” | 已停用 | C13 |
| P6 | 再“启用”，然后“一键回国”，在确认框里确认 | 已回国 | C12、C13 |
| P7 | 人工看：启用后图标是飞机，停用后是 Wi-Fi 划线，回国后是房子；回国完成时的通知；环境检测页的分组和开关（真机上有） | 不核对，回填 | C9、C11、C12 |

不通过时：脚本提示“还不满足：…”，可以在应用里再看看后按回车重新核对，或输入 s 跳过（记“跳过”）。任何时候按 Ctrl+C，脚本都会执行恢复。

**本人授权的真机核验**（m5-plan 原定放在 M5-11）：等 M5-3。系统授权的实现做完后在这里补步骤；现在不写空壳脚本。

## 与原型（`ui/design/index.html`）的不同

- 原型的主窗口是侧边栏（总览、主代理、分流出口、应用分流、环境检测、地区、引擎），这里是标签页；第一个页面原型叫“总览”，这里叫“首页”。
- 原型的“添加主代理的节点来源”是弹出的对话框，按钮叫“导入并验证”；这里是页面里的一块表单，按钮叫“添加”。
- 原型的本地文件单个上限 8 MiB、可以直接粘贴 YAML；这里上限 2 MiB（和后台的请求体上限一致），暂不支持粘贴。
- 原型的“通过本机网络下载这份订阅”说明“以 Clash 客户端身份下载”；这里的说明按后台的要求写（未启用时才需要、会暴露本机地址）。
- 原型的分流出口支持 Clash 订阅、配置文件、分享链接、手动节点四种导入；这里只有选配置文件（wireguard / openvpn / clash），其余随后续任务。
- 原型的设置窗口有诊断包按钮；后台没有诊断包的接口，这里写“暂不提供”。
- 原型的环境检测有设备体检的结果；这里显示“在以后的版本提供”。
- 局域网节点的确认框、终端退路的两步说明、确认框的倒数和过期，原型里没有（按设计文字做）。
