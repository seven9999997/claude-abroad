## 0. 底线与会话里能做的事

### 0.1 五条底线原样适用

| 底线 | Mac 上靠什么 | Windows 上打算靠什么 | 依赖的探查 | 探查不通过时的备选 |
|---|---|---|---|---|
| **不泄漏**（Claude 相关流量不能从本机真实 IP 出去，含 DNS、UDP、IPv6、崩溃和重启的间隙） | pf 默认拦截全部出站，只放行回环、utun、`_abroad` 用户、DHCP、局域网（6.1）；IPv6 逐个网络服务关闭（6.1）；域名置顶（5.2） | WFP **持久过滤器**加**开机过滤器**：默认拦截全部出站（v4、v6），只放行回环、我们的虚拟网卡、专用服务账户的 SID、DHCP、局域网；IPv6 由 WFP 一律拦截（不依赖逐个网卡关闭）；多网卡并行解析由 WFP 拦住。**缺口 WR9**：规则只装在本机进程发起出站连接的那一层，WSL2、Hyper-V 虚拟机、容器转发出去的流量不经过它，失败即断网时是否仍被拦要实测 | WR1、WR5、WR6 | 做不到按身份放行时：退到“按第一跳的地址放行”（第一跳 IP 动态加入过滤条件），直连拨号改为同样按目标地址放行，身份方案作废 |
| **失败即断网**（服务停止、崩溃、检查不通过时走代理的流量断开，不能回退直连） | pf 规则不随 abroadd 进程消失；utun 随进程消失后路由失效（6.2）；闸门（8） | WFP 持久过滤器不随服务进程消失；闸门和状态机共用（design 8、10） | WR1、WR2 | 虚拟网卡在服务崩溃后仍残留时：靠 WFP 拦截兜底（残留的网卡没有进程在读，流量进去就丢） |
| **回国干净**（网络、IPv6、时区、语言按原值恢复；卸载后一切解除） | pf 规则重启后自动消失；恢复流程逐项还原（10） | **WFP 持久过滤器重启后不会自动消失**，还原必须可靠：还原程序不依赖我们的服务、可以单独运行；每个过滤器都在我们自己的 provider 和 sublayer 下，按 provider 整批删除；时区和语言按原值还原（design 9.2 的做法） | WR1、WR7 | 还原程序本身失败时的最后手段：应急文档写明按 provider 删除过滤器的步骤（需要一个独立的小工具，Windows 没有现成的命令按 provider 删） |
| **不误杀**（查询服务临时故障、同国漂移不断网、不结束 Claude） | 共用逻辑（design 8、8.1） | 共用逻辑，不变 | — | — |
| **敏感操作要本人授权**（回国、卸载、改主代理、把应用改成本机网络，不能被脚本悄悄调用） | unix socket 0600 + 对端 uid（11.1）；M5 加签名校验 | 命名管道，带只允许管理员组和 SYSTEM 的安全描述符；取对端进程号和令牌核对身份；敏感操作要求 UAC 提升或本人确认（M5 对应部分） | WR5（服务账户与权限模型） | 退到“本机管理员组才能调用”，敏感操作在应用里二次确认 |

### 0.2 会话里能做什么、不能做什么

开发机是 Mac（Apple Silicon）。这台 Mac 上的 Windows 虚拟机是 ARM 版，里面也跑不了我们的虚拟机，不能用来验证。

**2026-11-21 起的验证环境**（用户提供、architect 定规程）：

- 一台 x64 的 Windows 10 专业版电脑（用户日常在用，装有代理软件和 VPN；地址、账户等只记在本地的 `docs/LOCAL.md`），会话经 SSH 用专用密钥连接。
- ~~托管的 Windows 构建环境~~（2026-11-22 用户决定不要自动构建，作废）：改为每次改动系统层之后，经 SSH 在用户提供的那台电脑上跑编译、vet、Windows 上的单测和系统层的冒烟测试（只碰我们自己的提供者和回环上一条不影响任何实际流量的过滤器）。

远程执行的规程：

1. **第一级探查（只用动态过滤器）可以由会话经 SSH 远程执行**，条件全部满足才做：规则保持“允许局域网”，会话的 SSH 连接本身在放行范围内；执行前先用离线求值器预测“从开发机地址到那台电脑 SSH 端口的回包”，必须是放行；探查以后台方式启动、输出写文件、自带 120 秒时限；开始前先远程跑一次还原工具的空跑；开始前在对话里告诉用户“接下来两分钟那台电脑会断外网”，得到答复再做。
2. **第二、三级（持久过滤器、开机过滤器、重启）不由会话自行远程执行**，W-2b 再定；至少要求用户人在电脑旁边（出了问题只能在本机处理）。
3. 不在那台电脑上留下多余的东西：程序放在一个专门的目录，结束后删除；不改它的系统设置；不动它上面的代理软件和 VPN。
4. 凡是会让那台电脑断网的操作，开始前都在对话里与用户确认时间，不因“允许随意操作”而省略。

第一级探查的执行条件（architect 2026-11-22 判 W-2a 时给出）：

1. **先演练**：探查程序的演练模式流程与正式执行完全相同（逐项尝试、判定、子进程、硬时限、写结果文件、脱敏），但装的不是断网规则，而是冒烟测试里那条“只拦回环上一个不用的端口”的过滤器，网络完全不受影响。演练的结果文件交 architect 看。实现（W-2a-2）：`abroad-wfp-probe --rehearse --yes`；装哪一组过滤器只由 `Plan.Filters` 决定（纯函数，有单测），演练模式只有一条拦回环 TCP 端口 1 的过滤器（键 `…5A1F00000002`，带我们的提供者和子层）；各项预测都是“照常”，另加一项 rehearse-hit（回环端口 1）预测“拦截”，证明这条过滤器确实生效。
2. **演练通过后**，正式的第一级才可以经 SSH 远程执行，仍按上面的规程（保持允许局域网；先远程空跑还原工具；后台启动、120 秒时限；开始前在对话里告诉用户接下来两分钟那台电脑会断外网，得到答复再做）。
3. 那台电脑上有一个代码沙箱工具自带出站拦截规则：结果里凡是“预测与实际不一致”的，先对照别家过滤器的清单再下结论。
4. 第一级加一个只观察的项目（WR9）：装了 WSL 就在规则生效期间从 WSL 里访问一次外网。实现：只调用 `%SystemRoot%\System32\wsl.exe`（`--list --quiet`，有发行版时 `-e sh -c` 用 bash 的 `/dev/tcp` 连一次 1.1.1.1:443，5 秒）；没有 wsl.exe 或没有发行版记“未执行”，调用失败记“无法判断”。正式模式下预测为“无法判断”（要观察的正是它），演练模式下预测“照常”。

- **能做**：`GOOS=windows GOARCH=amd64` 交叉编译和 `go vet`；与平台无关的逻辑在 Mac 上跑单测；文档；探查程序和用户脚本的编写、空跑（只打印将要执行的命令）。
- **不能做**：任何在 Windows 上的真实执行。所有会改 Windows 系统的操作（防火墙、网卡、路由、DNS、服务、时区、语言）都写成脚本，由用户在自己的 Windows 电脑上执行。
- **因此 Windows 的实现分两层**（和 Mac 的 sysnet 一样）：命令拼装、输出解析、判定逻辑写成**不带构建约束的纯函数**，在 Mac 上测；真正调用系统接口的那一薄层带 Windows 构建约束，由用户在 Windows 上验证。
- **带 Windows 构建约束的单测**：会话里跑不了。是否用托管的 Windows 构建环境自动跑，等用户决定（见 PROGRESS 的“需要用户人工处理”）；不同意时由用户在自己的电脑上手动 `go test`。
- **不能断网的约束**：会话不接触那台机器。给用户的脚本沿用 Mac 这边的全部安全约定：先起死人开关（到点自动还原）、中途失败自动还原、空跑模式、改动命令清单、还原脚本不依赖我们的服务。会断网的探查（WR1）在 README 里写明时长；如果那台是用户日常用的电脑，只在用户自己选的时间执行。

### 0.3 探查的安全要求（architect 判 W-0，带进 W-2）

Windows 的持久过滤器重启后不会消失：探查一旦出错，用户的电脑会一直断网，这比 Mac 上的任何一步都危险。所以：

1. **先交付独立的还原工具**：不依赖任何别的组件的小程序，只做一件事——删除我们这个 provider 名下的全部过滤器、子层和 provider 本身；可重复执行；它的空跑模式和命令行为先经 architect 审。
2. **WR1 的探查分三级，前一级通过才做下一级**：第一级只用**动态过滤器**（进程一退出系统自动删除，不可能留下残留）；第二级才用持久过滤器，并且先装好“到点自动还原”的计划任务；第三级才加开机过滤器和重启测试。
3. **每一级开始前**，脚本先确认：还原工具在本机能运行（先空跑一次），计划任务已经注册。
4. **README 把应急步骤写在最前面**：断网后怎么在本机执行还原工具；还原工具也不行时怎么办（先写“进安全模式执行还原工具”，并在第二级里验证安全模式下过滤器是否生效，再改写准确）。

### 0.4 W-1 的决定（architect 2026-11-21 判 M4-7 时给出）

1. **目标只有一个**：`GOOS=windows GOARCH=amd64 go build ./...` 和 `go vet ./...` 通过。Mac 和 Linux 的行为一行都不变。不实现任何 Windows 的功能。
2. **按平台拆文件，不动逻辑**：Unix 的实现原样挪进带构建约束的文件；Windows 一侧放占位实现。
3. **占位实现必须失败，不能假装成功**：每个占位函数都返回同一个“本平台尚未支持”的错误（`internal/platform` 的 `Unsupported`，`errors.Is(err, platform.ErrUnsupported)` 可判断）。尤其是状态文件的属主和权限校验、不跟随符号链接的打开、跨进程锁、对端身份校验、进程号和信号，占位绝不能返回“校验通过”。后果是 Windows 上这些功能现在一律不可用，这是对的。
4. **拆法**（按 W-0 清点出的四个根因）：
   - fdpass 和 directdial：与平台无关的部分不带构建约束；经 unix socket 传 fd 的传输层带 unix 约束；Windows 的传输层是占位（`fdpass_windows.go`）。stack、exitcheck、envcheck、daemon 因此都能编。
   - 状态文件、fake-IP 的落盘、虚拟机宿主的状态目录、环境检测的落盘：不跟随符号链接的打开、取属主、flock 三个原语从各包里原样挪进 `internal/platform`（`file_unix.go`），Windows 一侧是占位（`file_windows.go`）。调用方逻辑不变；vmhost 的属主检查原来在“取不到属主”时跳过，现在“本平台尚未支持”时明确报错（这条分支在 unix 上走不到）。
   - Cage 遗留的 `internal/host`、`internal/diagnostics`、`internal/managedproxy`：只补 Windows 的占位，彻底清理仍在 M4-8。
   - cmd 下的程序：abroadd 的真实模式在 Windows 上打印“尚未支持”并以退出码 3 退出，假系统模式能编能跑；abroad-vm、m0-r2-probe 只用于 macOS，在 Windows 上打印说明并以退出码 3 退出；abroad-dev 能编。入口行为由不带构建约束的纯函数（`platform.RealModeEntry`、`platform.MacOnlyEntry`）决定，有单测。
5. **“交叉编译通过”从此是每个任务的验收项**，Mac 这边的任务也一样（design 12.1）。
6. **源码检查**（`internal/srccheck` 的 `TestRepoWindowsPlaceholdersFail`）：遍历所有 Windows 上编译、macOS 上不编译的非测试文件（含和 Linux 共用的 `*_other.go`），断言每个函数要么返回“本平台尚未支持”且没有返回 nil 错误或 true，要么是不做系统调用的纯计算。例外逐个列名单并写理由：现在只有和 Linux 共用、本来就一律返回错误的 8 个函数（W-1 不改它们的文字，免得改变 Linux 上的行为），它们同样不能返回 nil 错误或 true。

### 0.5 W-2 的拆分和 W-2a 的决定（architect 2026-11-21 判 M4-8 时给出）

W-2 原定是“WR1、WR2、WR3 的探查程序和用户脚本”。先做 WR1，并拆开：它决定整体方案，也是唯一会让用户的 Windows 电脑断网、而且重启也不会自己恢复的探查。

- **W-2a**：过滤规则的模型、离线求值、独立的还原工具、第一级探查（只用动态过滤器）。
- **W-2b**：第二、三级探查（持久过滤器、开机过滤器、重启），以及 WR2、WR3。等用户跑完第一级再做。

W-2a 的决定：

1. **仿照 Mac 这边 pf 的做法，先把“规则是什么”做成与平台无关的数据和纯函数**（`internal/wfprules`，不带构建约束）。输入是配置（我们的虚拟网卡、放行的服务账户 SID、是否允许局域网及网段），输出是一组过滤器的描述（层、条件、动作、权重、所属子层），相同输入逐字节相同的输出。配一个离线求值器，只认我们自己生成的描述：给一个出站连接的属性（接口、发起者身份、协议、端口、目的、地址族），算出放行还是拦截。性质测试照搬 pf 的四条：IPv6 除回环外一律不放行；目的是公网、接口不是回环也不是我们的虚拟网卡、身份不是放行的服务账户时一律不放行；恶意 DHCP 发来的公网“直连网段”不放行；DHCP 只放行到广播和私有范围。**求值器对 WFP 仲裁规则的建模是假设**：同一子层内按权重取第一条命中的；任何子层的拦截都是最终结果。由第一级探查验证。
2. **薄的系统层**（带 Windows 构建约束）：只做建立我们的提供者和子层、添加一组过滤器（动态或持久）、枚举我们名下的过滤器、按提供者整批删除。每个系统调用的参数由纯函数算好；会话里只能交叉编译、不能运行。
3. **独立的还原工具**：单独的小程序，只依赖“枚举”和“整批删除”；默认空跑，只列出将要删除的对象，带明确的参数才真删；可重复执行，删完再枚举一次确认为空；不读配置文件，不依赖我们的服务。
4. **第一级探查程序**：只用动态过滤器（程序一退出系统自动删除）；自带时限（默认 120 秒）；启动时先调用还原工具的空跑。验证并记录：默认拦截是否生效；回环、局域网、DHCP 是否照常；以另一个身份运行的进程能否按 SID 被放行（用户按 README 用另一个本地账户执行一条命令）；IPv6 是否被拦；已建立的连接在过滤器装上之后是否被切断；枚举结果是否与期望的规则摘要一致。每一项同时记下离线求值器的预测和实际结果，不一致的单独标出。
5. **给用户的材料**：README 最前面是应急步骤；写清第一级不会留下残留（最坏情况是断网 120 秒，或结束探查程序即恢复）；写明需要管理员权限、预计时长、贴回哪个文件；输出文件里的本机地址和账户名先脱敏。
6. **在用户回答之前能做到哪一步**：代码和文档写完、交叉编译通过、纯函数的测试在 Mac 上跑；系统层在没有 Windows 环境时无法运行验证，交验收时如实写明。用户同意用托管的 Windows 构建环境时，系统层里不需要断网的部分（建提供者、加一条不影响网络的动态过滤器、枚举、删除）可以在那里自动验证；不同意时，第一次真正运行就是用户执行第一级探查的时候。

**W-2a 的三处调整**（architect 2026-11-21，用户回答 W-U1、W-U2 之后）：

7. **探查前后记录别的提供者**：开始前和结束后各枚举一次有哪些提供者和子层、各自在出站连接层有多少条过滤器（只记名字和数量，不记条件）。第一级里“预测与实际不一致”的项要能对照这份清单判断是模型错了还是被别的过滤器影响；结果不干净时请用户临时关掉代理软件和 VPN 再跑一次作对照。汇总是纯函数（有单测），枚举是薄的系统调用。
8. **远程执行的规程**：见 0.2，同时写进 `scripts/win/README.md`。第一级探查在 W-2a 里不执行，等 architect 看过交付再放行。
9. **系统层的冒烟测试**：带 Windows 构建约束的测试，只做不影响网络的事（建我们的提供者和子层；加一条只匹配回环上某个不用端口的动态过滤器；枚举能看到它；整批删除后枚举为空；还原工具的空跑和真删），无论成败都清理干净；每次改动系统层之后经 SSH 在那台电脑上跑（不断网；自动构建已作废）。

所有探查程序都由用户在 Windows 电脑上执行；会话里只写程序和脚本、做空跑。

|---|---|---|---|---|---|---|
| WR1 | WFP 持久过滤器能否做到：默认拦截全部出站；只放行回环、我们的虚拟网卡、某个服务账户 SID 的出站、DHCP、局域网；**服务崩溃后、开机时服务还没起来之前规则仍然生效**；按 provider 整批删除可靠 | 探查程序装上一组持久过滤器（带死人开关：N 分钟后自动删），用浏览器、`curl`、以服务账户身份运行的 `curl` 分别访问外网，记录哪些通；结束探查进程后再测一遍；重启电脑后再测一遍（死人开关在重启后由计划任务执行）；最后删除并确认外网恢复 | **是**（约 3–5 分钟，含一次重启） | 是 | 20 分钟 | 做不到按 SID 放行：改按第一跳地址放行；开机过滤器不可用：接受“开机到服务启动之间”的窗口并写进已知限制（不可接受时停下来重新评估） |

## 3. 哪些 Mac 的设计结论在 Windows 上不成立或需要重新实测

| Mac 上的结论（design 章节） | Windows 上 | 影响 |
|---|---|---|
| pf 规则**重启后自动消失**，重启是最后的还原手段（6.2、2 节“连命令行也用不了”） | WFP **持久过滤器重启后仍在**（这正是“开机即断网”要的），所以重启**不是**还原手段 | 还原程序必须可靠、独立；应急文档要给出按 provider 删除过滤器的工具和步骤；卸载必须删干净（WR1） |
| utun **随进程消失**，经它的路由随之失效（6.2） | Wintun 网卡是否随进程消失需要实测 | 不随进程消失时，崩溃后流量进入一块没人读的网卡（被丢弃），失败即断网仍成立，但恢复时要先清理残留网卡（WR2） |
| pf 的状态表：规则改了已有连接不受影响，启用时要 `pfctl -F states`（M2） | WFP 在 ALE 层按连接授权，已授权的连接在过滤器变化后是否被重新评估需要实测 | 闸门关闭时我们自己断开走代理的连接（design 8），不依赖防火墙；但“启用时已存在的直连”是否被切断要实测（WR1） |
| pf 按**用户**放行（`user _abroad`）（6.1、R2） | 等价物是 WFP 按**用户 SID**（ALE_USER_ID）或**应用 ID** 匹配 | 需要实测能否匹配到服务账户发出的连接，以及绑物理网卡的连接（WR1、WR5） |
| fd 传递：直连拨号模块把套接字传给 abroadd（6.3） | Windows 没有 unix 的 fd 传递（套接字复制的接口要求目标进程配合，语义不同） | 直连改成直连拨号模块自己转发字节流，性能和背压要实测（WR5） |
| IPv6 逐个网络服务关闭并记原值（6.1） | 改为 WFP 一律拦截 IPv6，不动网卡设置 | 回国时不需要还原 IPv6；但有的程序在 IPv6 被拦时回退慢，需要实测（WR1） |
| 时区、语言用 systemsetup、defaults，用户级经 `launchctl asuser`（9.2） | 时区名体系不同（要映射）；语言按用户、要在用户会话里改；系统级区域要重启 | 地区的目标计算（region 包的 IANA 时区、语言标签）可以共用，Mac 一侧的命令要换一套（WR7） |
| 开机保护由 guard（LaunchDaemon）最先加载 pf（6.2） | 由持久过滤器、开机过滤器承担 | 没有单独的 guard；开机过滤器的覆盖范围需要实测（WR1） |
| 冲突检查读 scutil 的代理设置和路由表（10.4） | 读注册表的 Internet 设置、WinHTTP 代理、路由表、别的虚拟网卡 | 判定逻辑（preflight 的 Finding）共用，读取换一套 |

## 5. 可移植性清点（W-1 更新，2026-11-21；W-0 的版本见 git 历史）

命令：对 `go list ./...` 的每个包，分别执行 `GOOS=windows GOARCH=amd64 go build <包>` 和 `GOOS=windows GOARCH=amd64 go vet <包>`（在 Mac 上交叉编译，没有在 Windows 上运行）。证据 `scripts/dev/out/w1-windows-build.txt`。

归类（不变）：**共用**（逻辑与平台无关，Windows 直接用）；**按平台各有实现**（接口共用，Windows 要写自己的实现）；**只属于 Mac**（Windows 上不需要或换成别的东西）；**虚拟机里**（Linux，Windows 版照用）。

“怎么编过的”：**原生**＝没有平台相关的代码或本来就能编；**靠占位**＝包里有 Windows 的占位文件；**经 X 的占位**＝自己没有占位，但依赖的包靠占位编过。靠占位编过的包在 Windows 上能编不等于能用：占位一律返回“本平台尚未支持”。

| 包 | 构建 | vet | 怎么编过的 | 归类 |
