# Claude 出国 项目介绍

> 适合谁读：刚接手这个项目的开发者。读完能知道它要做什么、仓库里现在有什么、下一步从哪里开始。
> 完整设计见 [design.md](design.md)。

## 一句话

给整台 Mac 装一块"出国网卡"：所有流量交给一台口袋大小的 Alpine 虚拟机，默认从安装时选好的**主代理**出去；想让个别应用换出口，再在虚拟机里加 OpenVPN、WireGuard 等分流出口；时区和语言跟着主代理的出口一起换；指定的应用可以回本机网络；服务一停，整机断网。

## 主代理与分流出口

出口分两类，地位不一样：

| | 主代理 | 分流出口 |
|---|---|---|
| 数量 | 有且只有一个，必须配置 | 0 个或多个，可选 |
| 什么时候配 | 安装时的引导里就要选好，之后在应用的"主代理"页面更换 | 随时在"分流出口"页面添加 |
| 谁在用 | 默认规则：没有单独设置的应用、识别不出来的连接、DNS 的非 A 记录查询，全部走它 | 只有在"应用分流"里指定了它的应用才走它 |
| 支持的来源 | Clash/Mihomo 订阅链接、本地 YAML/YML/JSON、手动 HTTP/SOCKS5 节点，以及链式代理（中转 → 最终出口）。节点支持 UDP 时转发 UDP，不支持时拦截 UDP | OpenVPN `.ovpn`、WireGuard `.conf`、其他 Clash 订阅、sing-box 支持的分享链接 |
| 运行方式 | 虚拟机里的 mihomo | 每个 VPN 一个独立网络命名空间；代理类由 sing-box 或另一个 mihomo 运行 |
| 检查不通过时 | 闸门关闭，所有走代理的流量断开 | 指定它的应用自动改走主代理 |
| 地区同步 | 时区和语言跟随它的出口 | 不影响地区 |

一个分流出口都不装也完全可以用：整台 Mac 的流量都走主代理。某个分流出口被删除、停掉或检查不通过时，指定它的应用自动改走主代理，应用里提示哪些规则正在回退（设计第 5.2 节）。

### 安装时配置主代理

安装引导的顺序：

1. 打开 `Claude 出国.app`，按提示在"系统设置 → 通用 → 登录项"里允许后台服务，应用注册后台服务并准备虚拟机镜像。
2. **配置主代理**（不能跳过）：选择导入方式 → 导入并验证 → 选节点（需要中转时切到"链式代理"，按顺序选中转和最终出口）→ "应用主代理"。
3. 首次没有可用代理时，订阅可以勾选"通过本机网络下载这份订阅"；不勾选就不下载，失败也不会自动换成本机网络。
4. 对主代理做出口检查，展示出口 IP、国家、城市、时区，以及 UDP 是否可用。UDP 不可用时提示视频会议、语音通话、游戏会受影响，但不阻止启用。
5. 用户确认后点"启用"，开始接管整机流量。

主代理没配好之前，"启用"按钮不可用。

## 工作原理

```
Mac 上的应用
   │  默认路由和 DNS 都指向虚拟网卡
   ▼
abroadd（Mac 上的后台服务）
   │  识别连接属于哪个应用 → 按规则决定：
   │    默认       → 主代理
   │    指定出口   → 某个分流出口
   │    直连       → 自己从物理网卡发出
   │    禁止       → 拒绝
   ▼
Alpine 虚拟机
   │  sing-box 按出口标签转发：
   │    main      → 主代理（mihomo）
   │    其他标签   → 分流出口（OpenVPN / WireGuard / 其他订阅 …）
   ▼
物理网卡 ─▶ 代理 / VPN 服务器

pf 防火墙：物理网卡只放行 _abroad 用户的连接，服务一停就断网
```

## 四个按钮

| 按钮 | 效果 |
|---|---|
| 启用 | 接管全部流量，主代理出口检查通过后放行，同步时区和语言。主代理没配好时不可用 |
| 停用 | Mac 断网（白名单里的应用除外） |
| 恢复本机网络（一键回国） | 二次确认后，先强制结束所有 Claude 相关进程（桌面版、Claude Code 等），确认都退出了，再撤掉所有改动，网络、时区、语言都恢复原样 |
| 切换地区 | 跟随出口，或手动选择时区和语言。确认框会列出将被强制结束的 Claude 进程，需要时引导重启电脑 |
| 一键卸载 | 二次确认后结束 Claude、恢复本机网络和地区、解除 Claude 启动管控、清理全部服务和数据 |

另外两条贯穿始终的规则：

- **环境检测**：启用后从本机应用的角度检查 17 项（参考 claude-switcher 的思路），其中 12 项硬性。硬性项不通过就关闭代理流量、不让 Claude 启动，但不会结束正在运行的 Claude。
- **Claude 的域名永远不走本机网络**：不管哪个应用访问、规则怎么设。
- **地区是锁定的**：只在启用、应用主代理、切换地区时改变，出口 IP 漂移不会自动改时区。
- **回国后 Claude 不能启动**：Claude 的域名在回国状态下解析不了，自己点 Claude 图标、在终端输入 `claude` 也会被马上结束，只有一键卸载才解除。这层管控防的是误操作（开机时 Claude 抢先启动、不小心关掉 Claude 出国等），不防有意绕过，场景见设计第 10.2 节。

### 搬来的 Go 包

| 包 | 在 Cage 里做什么 | 在本项目里做什么 | 后续要改的地方 |
|---|---|---|---|
| `internal/exitpolicy` | 判断出口 IP 是否在大陆地址段；用 ipwho.is / IP.SB 查询出口的国家、城市、时区 | 出口检查，以及"时区和语言跟随出口"的数据来源 | 基本不用改。User-Agent 里的 Cage 字样要换掉 |
| `internal/gate` | 来自 `internal/cage` 的网络闸门：closed / checking / open 状态机，放行 90 秒需要续期，出站 Egress，安全报告 | 放在 abroadd 里，控制走代理的流量是否放行 | 改成按出口分别判断（设计第 8 节）；运行记录的路径还沿用 Lima 目录的写法 |
| `internal/netguard` | 决定虚拟机能访问什么：只能访问公网，不能访问本机、局域网和其他虚拟机 | 限制 Alpine 虚拟机的出站（abroad-vm 使用） | 策略文件名和环境变量（`AGENT_VM_UNSAFE_OPEN_NETWORK`）要改名 |
| `internal/managedproxy` | 导入 Clash 订阅、本地 YAML、手动节点、链式代理；保存节点；运行和监控 mihomo 进程 | **主代理**的导入、节点选择和链式代理基本原样使用；Linux 版的进程管理（`platform_linux.go`）可直接用于虚拟机里的 abroad-agent | 分流出口另建模型（OpenVPN、WireGuard 等非 Clash 出口），不塞进这个包；Socket 路径和提示文案要改 |
| `internal/hostproxy` | 读取系统代理设置（含 PAC），"通过主机网络下载订阅"时使用 | 同样用于首次没有可用出口时下载订阅 | 基本不用改 |
| `internal/diagnostics` | 日志存储，自动脱敏 | 统一日志 | 日志目录要改 |
| `internal/usererror` | 把错误整理成"做什么失败了、原因、下一步怎么办"的中文提示 | Mac 应用和命令行的错误提示 | 不用改 |
| `internal/host` | （只搬了私有文件权限部分）创建 0700 目录、0600 文件，并检查权限 | 保存凭据和状态文件 | 不用改 |

这些包里还有约 100 行 Cage 专属内容（提示文案里的"Cage"、`CLAUDE_CAGE_*` 环境变量、Lima 目录结构），等开始接入时再逐个替换。Windows 相关的文件已经删掉，第一阶段只做 macOS。

### gvisor-tap-vsock 补丁

Cage 用 gvisor-tap-vsock 实现虚拟机的用户态网络。虚拟机的所有连接，实际都由 Mac 上的这个进程代为发起。Cage 在上面加了 5 个补丁：

| 补丁 | 作用 | 本项目是否需要 |
|---|---|---|
| 0001-outbound-policy | TCP/UDP 转发前先经过出站策略检查（配合 `internal/netguard`），禁止访问本机和局域网 | 需要 |
| 0002-dns-policy | 内置 DNS 只回答允许的域名，并记录解析结果，让"只允许指定域名"的策略生效 | 需要 |
| 0003-accept-ended-by-context | 程序主动停止网络时，不再把连接关闭当成错误记录 | 需要 |
| 0004-cage-proxy-egress | 给 TCP 拨号和 DNS 增加可替换的钩子。Cage 用它把所有 TCP 交给代理、DNS 改走 DoH，失败时不回退到本机 DNS | 部分需要：虚拟机的 TCP 直接走物理网卡，不用代理钩子；DNS 钩子可以用来实现"虚拟机解析服务器域名时走 DoH"（设计第 4.5 节） |
| 0005-ipv6-guest-link-drop | 丢弃虚拟机发出的 IPv6 帧，并回调通知（用于计数和检查） | 需要 |

## 下一步

按 [design.md](design.md) 第 14 节的里程碑推进，先做 **M0 技术验证**。最关键的两项：

1. **R1**：苹果的虚拟化框架能否在开机后、用户登录前，由后台服务以 `_abroad` 身份运行。
2. **R2**：pf 的"只放行 `_abroad` 用户"规则，能否匹配到虚拟机出站和直连应用的连接。

这两项决定了断网保护能不能按现在的设计实现，其他工作都排在它们后面。
