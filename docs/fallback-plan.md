>
> 来由：用户 2026-11-25 新增需求——回国后 Claude 还是要连不上（G9 不变），但如果拦截没拦住，要有兜底，不能从本机真实 IP 出去。参照的是用户自己的项目 [caibao_vps](https://github.com/daniel66666667/caibao_vps)（只给 Claude 进程注入代理环境变量、本机代理只把域名交给远端、任何失败都关闭不回退）。用户已确认可以参照、名字可以公开；本项目不复制它的代码，只借用策略。

## 1. 目标与两种读法

新增一条目标（拟定为 G9.1，定稿后写进第 1 节）：

> **回国状态下，没被拦住的 Claude Code 流量不能从本机真实 IP 出去。**

“没拦住时怎么兜”有两种读法，后果相反：

| | 甲：一律拒绝（**用户 2026-11-25 选定**） | 乙：经外部中继转发（不做） |
|---|---|---|
| 回国后没被结束的 Claude Code | 连不上 | 能用，对外是中继的 IP |
| 需要的东西 | 不需要中继和服务器 | 中继的地址、令牌、证书指纹；abroadd 回国后要往外拨 |
| 和 G9 的关系 | 一致：把“连不上”从只靠解析锁变成解析锁加本机代理两道 | 冲突：npm 装的 Claude Code 第三层不结束，回国后会一直能用 |
| 要做的任务 | M6-3b | M6-3b + M6-3c（中继上游） |

按甲做，M6-3c 不做。乙的设计不再展开；以后用户要改，按改第 1 节处理。

已启用状态下主代理或虚拟机故障**不切到中继**，仍然断网（architect 2026-11-25 定）：“失败即断网”是核心承诺，切到中继会让出口国家和地区设置在会话中途变掉。

## 2. “没拦住”的情况和覆盖范围

现有三层（10.2）：第一层解析锁、第二层启动拦截（没有授权，不做）、第三层发现即结束。

| 没拦住的情况 | 现有的层 | 第四层能不能接住 |
|---|---|---|
| npm、Homebrew 装的 Claude Code：签名确认不了，第三层不结束它（M6-4a） | 只靠解析锁 | **能**，这是第四层最主要的对象 |
| Claude Code 自带代理环境变量或系统代理，根本不做本机解析（R18 场景 C） | 解析锁失效 | **能**，前提是第 6 节实测 1 通过 |
| 本机开着带 DNS 劫持的 TUN，替解析锁地址应答（R18 场景 B） | 解析锁失效 | **能**：Claude Code 不做本机解析，直接连本机代理端口 |
| 第三层 200 毫秒的扫描窗口；运行很短的命令 | 可能漏掉 | **能** |
| abroadd 没在运行（第三层随之没有） | 只靠解析锁 | **能**：端口没人监听，连接被拒 |
| Claude 桌面版绕过解析锁（R9 未测） | 第三层会结束它（有签名） | **不能**：它是 Chromium，不读这份设置 |
| 浏览器开了加密 DNS 访问 claude.ai | 只有显式的“同时强制退出浏览器” | **不能** |

最后两行要接住，只能在回国后保留网络层的接管（网卡、路由或 pf），那就违反“回国干净”（R9 的备选方案已经写明不这样做）。所以不做，并在界面、回国确认框和文档里如实写明：**第四层只覆盖 Claude Code**，包括终端里的、IDE 插件启动的、桌面版里的 Code 会话（最后一种以实测 3 为准）。

## 3. 第四层的组成

### 3.1 Claude Code 的托管设置

Claude Code 支持系统级的“托管设置”（managed settings），优先级最高，用户和项目的设置改不掉。官方文档（architect 2026-11-25 核对）写明：

- macOS 上的路径是 `/Library/Application Support/ClaudeCode/managed-settings.json`；同一目录下还支持分片目录 `managed-settings.d/`，其中每个文件和主文件合并，`env` 按变量逐个合并（分片有最低版本要求，见实测 4）。
- 设置里的 `env` 会写进进程环境，**替换从 shell 继承来的同名变量**（少数变量例外，代理变量是否在例外里待实测 1）；桌面版管理连接的会话里，启动环境已有的变量会让设置文件的值被忽略。
- 代理变量的读取顺序是 `https_proxy`、`HTTPS_PROXY`、`http_proxy`、`HTTP_PROXY`，取第一个已设置的；`NO_PROXY="*"` 表示全部绕过。不支持 SOCKS。
- 托管设置文件解析失败时 Claude Code **拒绝启动**；因权限读不了时会话照常启动但**不带这份策略**（静默失效）。
- Claude Code 监视设置文件，改动会被**正在运行的会话重新加载**。

我们的做法：

- **只写一个分片文件** `managed-settings.d/claude-abroad.json`（暂名），主文件和别人的分片一概不碰。本机 Claude Code 版本不支持分片时，备选是主文件：路径上已有别人的文件就不覆盖，冲突检查里列出并给出手动合并的说明。
- **内容**：四个代理变量的大小写都写，指向同一个地址；`no_proxy`、`NO_PROXY` 两个都只放回环地址。只写这六项：

  ```json
  {
    "env": {
      "https_proxy": "http://127.0.0.1:47821",
      "HTTPS_PROXY": "http://127.0.0.1:47821",
      "http_proxy": "http://127.0.0.1:47821",
      "HTTP_PROXY": "http://127.0.0.1:47821",
      "no_proxy": "localhost,127.0.0.1,::1",
      "NO_PROXY": "localhost,127.0.0.1,::1"
    }
  }
  ```

  端口 47821 是固定值（写在静态文件里，不随状态改）。不用 7890、7891（常见代理和 caibao 的默认端口），也不用 8787。地址里不带口令：这份文件普通用户可读，口令没有保密意义；端口按连接方走规则（3.2），不会成为别的程序绕过规则的通道。
- **写法和权限（硬要求）**：先校验是合法的 JSON，再原子写入（同目录临时文件加改名）——一份坏文件会让这台机器上所有 Claude Code 都起不来。属主 root、普通用户可读。各有测试。
- **生命周期**：和解析锁一样。首次准备（M6-8）时写入，回国、停用、退出应用都不删，只有一键卸载（M6-5）才删。文件是静态的，不随状态改写。
- **冲突**：分片目录下别的文件（以及主文件）如果也定义了这六个变量中的任何一个，就报告冲突，不改别人的文件。卸载只删我们自己的分片（内容哈希和 `/Library/Application Support/claude-abroad/` 里记的一致）。
- **自检**：每次 abroadd 启动和环境检测时核对：文件在、内容对、**普通用户读得到**、没有别的文件覆盖这六个变量。任何一项不满足，界面标出“第四层未生效”，不自动重写（重写算敏感操作，要本人授权）。

**连接方的子进程**：`env` 对会话和它的子进程（Bash 工具里的 git、npm、curl，MCP server）都生效，它们也会连到这个端口。端口因此按连接方的进程走规则（3.2），不一律走主代理，用户已有的规则（设成本机网络的应用、本地域名名单里的公司内网域名）照旧。回国后，从 Claude Code 里启动、仍在后台运行的程序会因为带着代理变量而连不上网，从普通终端重新启动即可；这一点写进界面的说明。

### 3.2 本机代理端口

abroadd 在 `127.0.0.1:47821` 上监听一个 HTTP 代理（`CONNECT`，以及带完整 URL 的明文 HTTP 请求），不接受 SOCKS。

- **未启用的各状态（`DISABLED`、`ENABLING`、`RESTORING`、`RESTORED`）一律拒绝**，不看是谁：回 `403`，带一个说明头（例如“现在是回国状态，Claude 出国不允许 Claude 联网”），不回退直连，abroadd 也不往外拨。
- **已启用时按连接方的进程走规则**：收到连接后识别对端进程（回环连接的本地端口对应的进程，沿用现有的进程识别），再用和接管流量**同一个**判定入口决定去向：
  - Claude 的进程、置顶域名照旧只能走主代理，闸门关着时拒绝；
  - 别的进程按各自的规则：主代理、分流出口、本机网络、阻止；
  - **识别不出来的按 Claude 处理**：只走主代理，闸门关时拒绝。
  - 走代理时经现有的数据通道转发：目标是域名就把域名原样交给出口解析，不在本机解析。
- 只监听回环地址。端口被别的程序占着时，abroadd 照常启动，界面标出“第四层未生效”；冲突检查里这一项按**必须处理**显示——占用者如果恰好是个代理，Claude Code 的流量会交给它。
- 连接只记数量、规则动作和拒绝原因；日志不写出口 IP。

### 3.3 状态表（甲）

Claude Code 连 `127.0.0.1:47821` 时：

| 状态 | abroadd 在 | abroadd 不在 |
|---|---|---|
| `DISABLED` | 拒绝（403） | 连接被拒（端口没人监听）；另有断网规则兜着 |
| `ENABLING` | 拒绝（403） | 连接被拒；断网规则在 |
| `ENABLED`，闸门开着 | 按连接方的进程走规则：Claude 的进程、识别不出来的、置顶域名走出口 main；别的进程按各自的规则 | 连接被拒；断网规则在（G2） |
| `ENABLED`，闸门关着（检测未通过、复查失败） | Claude 的进程、识别不出来的、置顶域名拒绝（403）；别的进程按各自的规则（和闸门关时的接管流量相同） | 同上 |
| `RESTORING` | 拒绝（403） | 连接被拒 |
| `RESTORED` | 拒绝（403） | 连接被拒（回国后没有断网规则，靠的是 Claude Code 不回退直连，见实测 2） |

不经过这个端口的流量（第四层没覆盖到的程序）仍按原来的三层处理，表里不重复。

作为对照，乙在 `RESTORING`、`RESTORED` 两行（abroadd 在）是“经外部中继转发，中继不通就拒绝”，其余各格和甲相同。

## 4. 五条底线逐条对照

| 底线 | 第四层怎么守 |
|---|---|
| 回国干净（回国后不留网络层的接管） | 托管设置是一份 Claude Code 自己读的配置文件，和解析锁一样静态、只有卸载才删；回国后不保留网卡、路由、pf，abroadd 不往外拨 |
| 失败即断网 | 任何一环不通都是“连不上”：abroadd 不在→端口不通；状态不对→403；主代理不通→和现在一样断网。没有任何回退直连的路径 |
| 不泄漏 | Claude 的进程和识别不出来的只走出口 main，域名交给出口解析、不在本机解析；别的进程和接管流量用同一个判定入口，不多开口子 |
| 敏感操作要本人授权 | 写入托管设置随首次准备一起授权；手动重写、删除（卸载）都按敏感操作走 11.1 的授权；写入前校验 JSON、原子写入，坏文件不会落盘 |
| 不防有意绕过的管理员 | root 可以删掉托管设置，这在第 2 节的边界之内；第四层防的是误操作和程序自带代理的情况 |

## 5. 与用户现有用法并存

- **这台 Mac 上 Claude Code 现在的用法**：经本机的另一个代理用环境变量启动。按官方文档，预期托管设置的 `env` **会盖过**启动环境里的变量，而且**写入后正在运行的会话也会重新加载**。所以写入的那一刻起，这台 Mac 上所有不在“已启用”保护下的 Claude Code 会话（**包括开发会话**）就会连不上，不只是新开的。规定：
  - 会话里任何情况下都不向真实路径写入。M6-3b 的代码里真实路径只在真实模式入口接上；测试和假系统模式一律用注入的临时目录；假系统模式默认不监听这个端口。有源码检查。
  - 真机脚本里，写入这一步之前用醒目的文字说明后果并要求输入确认；脚本结束和死人开关到点时删除这份文件。
  - 实测在哪台 Mac 上做由用户决定（第 9 节第 6 条）。
  - 实测 1 的结论如果反过来（盖不过启动环境），第四层对“自带代理变量”的那一类就接不住，第 2 节表里第二行改成“不能”。
- **caibao 的本机代理**：用户确认这台 Mac 上不另装（2026-11-25）。将来如果另装，有两处会冲突：它在 macOS 上也写 `/etc/resolver`，和解析锁是同一批文件；它只管经它启动的进程。冲突检查（10.4）加一项：`/etc/resolver` 下已有别人写的同名文件时停下来，不覆盖。
- **端口冲突**：47821 被占用时不抢、不结束占用者（第 3.2 节）。

## 6. 需要实测的事（M6-9，会话里不做）

会话里不能做这些实验：要启动真的 Claude Code 去连网，一旦回退直连就是从本机出去；写入托管设置还会影响开发会话本身（第 5 节）。都做成真机脚本，由用户执行。

| # | 要确认的事 | 在哪种状态下做 | 步骤 | 算通过 | 不通过时 |
|---|---|---|---|---|---|
| 1 | 启动环境里已有代理变量时，托管设置里的值是否仍然生效（预期会盖过） | **已启用**（所有流量都在接管下，即使绕开 47821 出口也仍是主代理，不暴露本机 IP） | 写入托管设置；分三种情况启动 Claude Code 各发一句话：带大写 `HTTPS_PROXY=http://127.0.0.1:<另一个端口>`；带小写 `https_proxy=…`；带 `no_proxy=*` | abroadd 的 47821 记到这次连接；另一个端口没有连接 | 第 2 节第二行改为“不能”；回国确认框和 10.2 限制里写明“自带代理变量的 Claude Code 只靠第一、三层” |

| 3 | Claude 桌面版里的 Code 会话读不读这份托管设置 | 已启用 | 在桌面版里开一个 Code 会话 | 47821 记到连接 | 第 2 节写明桌面版里的 Code 会话不覆盖 |
| 4 | 本机 Claude Code 支持分片目录；分片里的 `env` 已加载；普通用户读得到 | 任意（只读核对，不连网） | 看 Claude Code 版本是否达到分片的最低版本；写入后用 Claude Code 的设置查看命令确认已加载 | 设置显示为托管来源，六个变量生效 | 不支持分片时改用主文件（3.1 的备选） |
